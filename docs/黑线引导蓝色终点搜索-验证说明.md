# 黑线引导蓝色终点搜索验证说明

## 已实现策略

蓝色 A4 检测始终运行且优先级最高。自主搜索过程为：

1. `SEARCH`：使用原有地图安全航点搜索，作为永久兜底。
2. `OBSERVE`：每到一个航点停车 3 秒，同时观察蓝纸和黑线。
3. `LINE_SCAN`：检测到稳定长黑线后取消底盘目标，停车 10 秒，利用 STM32 原有的无目标水平扫描寻找蓝纸。
4. `ACQUIRE`：蓝纸出现后立即抢占 `SEARCH/OBSERVE/LINE_SCAN`，等待云台锁定并取得稳定位置样本。
5. `APPROACH`：生成蓝纸前方安全停车点，交给 `move_base` 避障到达。
6. 黑线扫描超时后自动返回 `SEARCH`，不会因黑线识别失败而停止任务。

当前 STM32 协议没有指定云台绝对角度的命令，因此本版本复用固件已有的水平搜索。无需重烧 STM32。若以后要求自动切换“向下看黑线”和“水平看蓝纸”两个精确俯仰姿态，需要扩展 STM32 协议并重新烧录。

## 新增话题

```bash
rostopic echo /black_line/observation
```

关键字段：

- `detected`：是否连续确认黑线。
- `confidence`：最长有效线段相对图像宽度的比例。
- `center_x/center_y`：黑线图像中心。
- `angle`：黑线在图像中的角度（弧度）。
- `pixel_length`：线段像素长度。

## 只验证视觉，不允许底盘自动起步

启动普通导航时保持：

```text
enable_blue_autonomy:=false
```

或者使用比赛入口但禁止自动开始：

```bash
roslaunch maze_bridge competition_autonomous.launch \
  map_file:=/home/hyj/xiaoche/maps/competition_map_v2.yaml \
  base_port:=/dev/ttyUSB0 \
  gimbal_port:=/dev/ttyUSB1 \
  camera_device:=/dev/video4 \
  auto_start:=false \
  blue_show_debug:=true
```

查看视觉结果：

```bash
rostopic echo /black_line/observation
rostopic echo /blue_target/observation
```

调试画面中：蓝纸用绿色矩形标记，确认的黑线用黄色线段标记；`Black Line Mask` 只应保留图像下部地面区域的黑色线。

## 低速自主状态机测试

确认地图、定位、雷达、底盘、摄像头和云台均正常后：

```bash
rostopic echo /blue_autonomy/state
```

另一个终端开始任务：

```bash
rostopic pub -1 /blue_autonomy/enable std_msgs/Bool "data: true"
```

应能观察到类似状态顺序：

```text
WAIT_SYSTEM -> SEARCH -> OBSERVE -> LINE_SCAN
```

出现蓝纸后应立即转为：

```text
ACQUIRE -> APPROACH -> COMPLETE
```

没有黑线或黑线扫描 10 秒仍没有蓝纸时，应回到 `SEARCH`。

## 紧急停止

```bash
rostopic pub -1 /blue_autonomy/enable std_msgs/Bool "data: false"
rostopic pub -1 /cmd_vel geometry_msgs/Twist '{}'
printf '\xAB\x00\xAB' > /dev/ttyUSB1
```

最后一条命令中的串口必须是当次确认的云台串口，不可凭编号猜测。

## 默认视觉参数

- 黑色亮度上限：`black_v_max=70`
- 地面 ROI 起点：图像高度的 `0.45`
- 最短线段：图像宽度的 `0.18`
- 黑线确认：4 帧
- 黑线清除：6 帧
- 普通航点观察时间：3 秒
- 黑线水平扫描时间：10 秒
- 同一黑线重复触发冷却：12 秒

正式比赛前必须在实际场地采集强光、阴影、黑色障碍物和终点线画面重新标定阈值。黑线只是加速提示，雷达与 `move_base` 仍负责路径和动态避障。
