# 实车比赛完整操作与自检手册（无前置点闭环版）

> **适用版本**：`asuka-main`（提交 `6b10b26` 及以上）  
> **适用场景**：正式比赛与全真模拟测试（无前置点、在线动态绕障、终端一键发车、自动分轮 rosbag 录包）  
> **运行环境**：所有比赛节点均运行在隔离的 ROS1 Noetic Docker 容器（`xiaoche/ros1-noetic:latest`）中，宿主机终端提示 `ROS 2 Jazzy environment loaded` 不会产生干扰。

## 零、 赛前硬件与环境一键自检（必做第 0 步）

给底盘、云台、雷达上电，插紧雷达网线与底盘/云台/相机 USB 后，在**终端 1**直接复制运行以下全部命令：

```bash
cd '/home/asuka/Desktop/college-level competition/xiaoche'
export LAKIBEAM_WS="$PWD/outputs/competition-lidar-ws"

# 建议使用简短固定的场次名（如 match-01 / test-01），避免切终端时时间戳不一致
export FIELD=match-01

# 1. 拉起雷达静态 IP 网口并检查物理链路
nmcli connection up 'LakiBeam-RJ45' ifname enp0s31f6 >/dev/null 2>&1 || true
echo "=== 1. 雷达网口与物理链路 ==="
ip -br addr show enp0s31f6
if ip -br link show enp0s31f6 | grep -q ' UP '; then
  echo "✅ 雷达网口物理链路 UP"
  ping -c 1 -W 1 192.168.198.2 >/dev/null 2>&1 \
    && echo "✅ 雷达 IP (192.168.198.2) 可达" \
    || echo "⚠️ ping 未回应（部分固件禁 ping，进 map/ready 后以 /scan 为准）"
else
  echo "❌ 雷达网口仍为 DOWN：请检查雷达电源开关与网线是否插紧！"
fi

# 2. 检查底盘 (8132) 与云台 (8134) 串口（脚本会自动按 revision 识别，无需关心 USB0/USB1 顺序）
echo "=== 2. 串口设备 ==="
for rev in 8132 8134; do
  name=$([ "$rev" = "8132" ] && echo "底盘" || echo "云台")
  found=""
  for d in /dev/ttyUSB*; do
    [ -c "$d" ] && udevadm info -q property -n "$d" | grep -Fxq "ID_REVISION=$rev" && found="$d"
  done
  [ -n "$found" ] && echo "✅ ${name}串口 ($rev) -> $found" || echo "❌ 未检测到${name}串口 ($rev)"
done

# 3. 检查 USB 相机与手柄
echo "=== 3. 相机与手柄 ==="
cam="/dev/v4l/by-id/usb-HRY_USB_Camera_20191109-video-index0"
[ -c "$cam" ] && echo "✅ USB 相机 -> $(readlink -f "$cam")" || echo "❌ 未检测到 USB 相机"
[ -c /dev/input/js0 ] && echo "✅ 手柄 -> /dev/input/js0" || echo "ℹ️ 未连接手柄（手推建图无需手柄）"

# 4. 检查是否存在未关闭的残留比赛容器
echo "=== 4. 残留容器检查 ==="
docker ps --filter "name=car-competition" --format 'table {{.Names}}\t{{.Status}}\t{{.Label "competition.field"}}\t{{.Label "competition.phase"}}'
```

### 自检合格标准
- `enp0s31f6` 状态必须是 **`UP`** 且带有 `192.168.198.1/24`（若显示 **`DOWN`** 说明网线没接通或雷达没通电，必须处理好再往下走）；
- 底盘 (`8132`)、云台 (`8134`)、USB 相机全部为 `✅`；
- 残留容器列表为空（若有旧容器在跑，先执行 `bash tools/competition_terminal.sh stop <旧场次名>`）。

> **仅当修改过源码后才需重新编译**：
> ```bash
> bash tools/competition_terminal.sh prepare
> ```

## 一、 建图阶段（启动建图节点 → 检查状态 → 推车建图 → 保存）

### 1. 硬件准备
- 确认车体自锁使能开关 **`PE14` 弹起（灯亮 = 自由推车模式）**；
- 若使用蓝牙/USB 手柄遥控建图，确认上一步已检测到 `/dev/input/js0` 并按住 `LB` 慢速遥控；
- 若手推建图，人尽量**蹲低或在车体正后方雷达 90° 盲区内缓慢匀速推动**，减少腿部遮挡激光。

### 2. 启动建图全套节点
包含：底盘编码器里程计 + 雷达驱动 + 车体自反射过滤 + `slam_toolbox`（里程计锚定防飘参数）+ RViz：

```bash
bash tools/competition_terminal.sh map "$FIELD"
```

- 无图形界面或不需要 RViz 时，可改为：
  ```bash
  COMPETITION_SHOW_RVIZ=false bash tools/competition_terminal.sh map "$FIELD"
  ```
- 若不小心关掉了 RViz 窗口，可随时单独重新打开（不影响建图）：
  ```bash
  bash tools/competition_terminal.sh rviz "$FIELD"
  ```

### 3. 检查建图状态与实时日志
```bash
# 查看地图分辨率、尺寸是否已有实时输出
bash tools/competition_terminal.sh status "$FIELD"
```
如需查看建图容器实时日志，可另开**终端 2**运行：
```bash
docker logs -f car-competition
```

### 4. 保存地图与起点（无前置点、无需 `turn`）
推车完整覆盖赛道后，**推回起点框并严格按发车朝向摆正停稳**，在终端 1 执行：

```bash
bash tools/competition_terminal.sh save "$FIELD"
```

- 成功后会在 `outputs/competition-fields/$FIELD/` 生成 `map.pgm`、`map.yaml`、`start_pose.json` 并自动关闭建图容器与 RViz；
- 脚本会自动校验起点周围 **`0.25 m`** 是否全部为已建图的自由空间，若报错请将小车在起点框内稍微摆正或确认起点周围已扫到自由空间后重试。

### 5. 中途取消或建图飘移时：停止并重新建图
```bash
# 1. 先查清后台正在运行的真实场次名（防止名字不匹配）
docker ps --filter "name=car-competition" --format '{{.Names}}  field={{.Label "competition.field"}}  phase={{.Label "competition.phase"}}'

# 2. 停止旧建图任务（将 <旧场次名> 替换为上一步查到的 field 值）
bash tools/competition_terminal.sh stop <旧场次名>

# 3. 换一个新场次名重新开始建图
export FIELD=match-02
bash tools/competition_terminal.sh map "$FIELD"
```

## 二、 备赛阶段：启动导航全套节点（整场仅需执行一次）

此时裁判开始摆放新增动态障碍物；将小车放在起点框摆正，**按下车体 `PE14` 使能开关（灯灭 = 竞速使能模式）**。

### 1. 启动常驻导航栈
包含：底盘串口桥（含 STL 轮廓防撞）+ 里程计 + 雷达驱动 + 自反射过滤 + USB 相机 + 蓝纸检测器（`7×11 px`, `S>=90`, `V>=55`, `confirm=4`, 顶/底边 ROI 过滤）+ 云台串口桥（带串口坏帧过滤与掉电重启自动恢复使能）+ AMCL + `move_base`（`SmoothGlobalPlanner` + `ForwardTebLocalPlanner`）+ 在线探索与绕障导航器（含物理高度/地图边界过滤与假目标证伪）+ 交接仲裁器 + 末端激光视觉入库控制器：

```bash
# 方式 A：直接启动当前场次（若 $FIELD 尚未建图，交互终端会自动弹出已有地图菜单供选择并复制）
bash tools/competition_terminal.sh ready "$FIELD"

# 方式 B：测试时直接从已有地图列表中交互选择（按保存时间倒序，回车默认选最新地图）
bash tools/competition_terminal.sh ready

# 方式 C：命令行直接复用指定地图到新场次（录包独立存放在 $FIELD/bags/）
bash tools/competition_terminal.sh ready "$FIELD" --map mock-1126-1456
```

- 随时可用 `bash tools/competition_terminal.sh maps` 查看全部已保存地图及起点坐标、录包轮数；
- 启动 `ready` 后，后续的 `status`、`go`、`stop` **均可省略 `"$FIELD"`**，脚本会自动匹配当前运行中的场次。

### 2. 检查全部导航与感知节点状态
```bash
bash tools/competition_terminal.sh status "$FIELD"
```

**正常输出核对清单**：
1. `/blue_autonomy/state/data`：显示 **`"IDLE: automatic handoff disabled"`**（待命未发车）；
2. `/gimbal/servo_ready/data`：显示 **`True`**（云台串口与双舵机就绪；进入 `go` 后还会进一步校核 `/gimbal/enabled == True` 与俯仰平视）；
3. `/amcl_pose/pose/pose`：输出合理坐标（与起点位置一致）；
4. 末尾打印 **`雷达数据正常。`**。

### 3. 建议开启终端 2 盯控实时日志（可选）
```bash
docker logs -f car-competition
```

### 4. 场馆光照下蓝纸检测快检（模拟测试强烈建议执行一次）
发车前可先看 5 秒 `/blue_target/observation` 确认**无蓝纸时不误检、贴蓝纸时稳定 `detected: True`**（发车运行中则以通过物理高度和地图边界校验后的 `/blue_target/validated_observation` 为准）：
```bash
docker exec car-competition bash -c '
  source /opt/ros/noetic/setup.bash &&
  source /workspace/compiled/devel/setup.bash &&
  timeout 6 rostopic echo /blue_target/observation
'
```
*(重点关注 `detected`、`center_y`、`pixel_width`、`pixel_height`、`contour_ratio` 字段。)*

## 三、 建图后的一键启动 + 自动 rosbag 录包（支持 3 轮连测）

> **关于 rosbag 录包的重要说明**：
> - `go` 命令**已内置全自动分轮 rosbag 录包**！进入 `go` 后会在 `[READY]` 亮绿灯前自动启动录包容器，每轮独立存放在 `outputs/competition-fields/$FIELD/bags/attempt-01-.../`、`attempt-02-.../`；
> - 按 `Ctrl+C` 结束本轮时，脚本会自动优雅封口保存 `.bag` 文件，不会损坏录包；
> - **切勿在运行 `go` 之前手动执行 `record`**，否则会因录包容器已被占用导致 `go` 报错退出。

### 第 1 轮发车（终端 1）
```bash
bash tools/competition_terminal.sh go "$FIELD"
```

操作流程：
1. **赛前待命与门禁校验**：脚本自动复位起点定位、清空代价地图动态层并预热本轮 rosbag 录包，直到终端显示绿灯提示：
   ```text
   [READY] 雷达:OK | 云台:OK (enabled, 俯角=+10.0°) | AMCL误差:0.02m | 录包:attempt-01-... | 敲击 [Enter / 空格] 发车 | [r] 复位起点并清图
   ```
   - 若显示 `[等待]`，终端会直接列出具体阻断原因（包括 `云台未连接` / `云台舵机未就绪` / `云台未使能(mode=0)` / `云台角度无实时数据` / `云台俯角未归位(...)` / `定位未收敛` / `车未停稳` / `底盘未进入待命` / `雷达无有效数据`）；
   - **云台俯仰限位与初始化俯头**：ROS 侧 `gimbal_bridge` 会在连接、复位、退回待命及丢失目标后自动将云台俯头到默认 **`-10°`（ROS 俯角 `+10°`）**，并在追踪时严格限制在 **`[-25°, 0°]`（绝不仰头）**，同时屏蔽高于水平线 `4°` 以上的蓝色杂物（如蓝色售货机/高位垃圾桶）；未锁目标时若偏离默认俯角超过 `±4.0°` 或 `mode=0`，发车会被拦截；
   - 若偏离起点超过 `0.30 m`，车体停稳后或冷却 `1.5 s` 会自动复位；微调车位或云台俯角未归位时，也可在发车前随时按 **`r`** 键立即手动复位起点、清图并请求云台回中俯头（约 `2 s` 内自动完成回中使能并俯头到 `-10°`）。
2. **终端一键发车**：裁判贴完蓝色 A4 纸并喊开始 → 敲一次 **`Enter` 或 `空格`**（隔离仿真中清图与发布发车信号耗时约 `6.5–9.9 ms`，实车端到端起步响应仍以现场实测为准；发车后按 `r` 无效，严禁任何外部干预）。
3. **运行监控**：终端自动打印阶段切换：
   `EXPLORE -> TARGET_APPROACH -> TERMINAL_PARK -> COMPLETE`
   小车停稳在 `0.8 × 0.8 m` 框内后，终端开始自动读秒：
   ```text
   静止 1.0 s
   静止 2.0 s
   静止 3.0 s，已满足静止计时，可按 Ctrl+C 结束本轮。
   ```
4. **结束本轮**：裁判确认成绩后，在终端 1 按 **`Ctrl+C`** 退出 `go`：
   - 终端打印 `已回到 IDLE，底盘目标速度归零。` 及 `本轮录包已保存到 ...`；
   - 退出发车回到待命时，`gimbal_bridge` 会自动请求一次云台回中平视并重新使能，为下一轮做好准备；
   - 底层常驻导航容器 `car-competition` 保持热机不退出。

### 第 2 / 3 轮复跑（模拟裁判更换动态障碍与终点位置）
1. 确认终端 1 已退出 `go` 并提示 `已回到 IDLE`；
2. 队员进场**弹出 `PE14`（灯亮）**，将小车推回起点框摆正，**重新按下 `PE14`（灯灭）**；
3. 裁判换好动态障碍与蓝色终点纸后，在终端 1 **再次运行同一条命令**：
   ```bash
   bash tools/competition_terminal.sh go "$FIELD"
   ```
   *(自动重新对齐起点、清空上一轮旧动态障碍残影、新建 `attempt-02` 录包；看到 `[READY]` 后敲 **`Enter` / `空格`** 即可发车。)*

## 四、 急停、整场收尾与录包核查

### 1. 突发异常急停
- **软急停**：在运行 `go` 的终端 1 直接按 **`Ctrl+C`**（立即发布 `/blue_autonomy/enable=false` 归零车速并回到 `IDLE`）；
- **硬件急停**：直接弹出车体自锁按钮 **`PE14`**（灯亮，立即切断电机驱动使能）。

### 2. 整场测试全部结束
关闭常驻导航容器与所有后台录包容器：
```bash
bash tools/competition_terminal.sh stop "$FIELD"
```

### 3. 核查本场全部录包文件
```bash
ls -lh "outputs/competition-fields/$FIELD/bags"/attempt-*/*.bag
```
若需快速查看某轮录包包含的话题与时长：
```bash
docker run --rm --network none \
  --mount "type=bind,src=$PWD/outputs/competition-fields/$FIELD/bags,dst=/bags,readonly" \
  xiaoche/ros1-noetic:latest bash -c '
    source /opt/ros/noetic/setup.bash &&
    for f in /bags/attempt-*/*.bag; do echo "=== $f ==="; rosbag info "$f" | head -n 15; done
  '
```

## 五、 现场常见报错速查表

| 终端提示 / 现象 | 原因 | 立即处理方法 |
| :--- | :--- | :--- |
| `enp0s31f6 DOWN 192.168.198.1/24` | 雷达未上电或网线松动 | 给雷达上电并插紧网线，重跑 `ip -br addr show enp0s31f6` 确认变为 **`UP`** |
| `场次 xxx 的 mapping/navigation 进程未启动` | 当前终端的 `$FIELD` 与后台容器场次名不一致 | 用 `docker ps --filter "name=car-competition" --format '{{.Label "competition.field"}}'` 查真实名字，执行 `export FIELD=<真实名字>` |
| `已有 ROS 任务运行，请先停止` | 上一场建图或导航容器未关闭 | 先查旧场次名并执行 `bash tools/competition_terminal.sh stop <旧场次名>` |
| `已有录包容器在运行` | 在 `go` 之前手动跑了 `record`，或上一轮录包未停干净 | 执行 `docker stop --signal INT --timeout 35 car-competition-bag` 后重跑 `go` |
| `起点周围 0.25 m 内存在障碍或未建图栅格` | 保存地图时车没摆在已建图的自由空间内 | 确认小车在起点框内且雷达已扫清起点周边，再重跑 `save` |
| `[等待] 定位未收敛` | 推回起点时偏差较大或人站在车旁遮挡雷达 | 人员走开离车 `> 1 m`，按 **`r`** 手动复位起点并清图，等 1–2 秒即可变 `[READY]` |
| `[等待] 云台未使能(mode=0)` | 单片机刚复位或刚上电，默认处于禁用态 | 等待约 `1.5–2.5 s`，`gimbal_bridge` 会自动补发回中与使能；若持续未恢复，按 **`r`** 触发回中或查看 `docker logs car-competition` 串口告警 |
| `[等待] 云台俯角未归位(...)` | 未锁目标状态下云台俯角偏离默认 `-10°`（ROS `+10°`）超过 `±4°` | 等待约 `1.5–2 s` 让 `gimbal_bridge` 自动俯头归位，或按 **`r`** 重新回中并俯头到 `-10°` |
| 发车后小车不动但终端显示 `EXPLORE` | 车体物理使能按键 `PE14` 忘记按下（灯亮着） | 按 `Ctrl+C` 退回 `IDLE`，按下 `PE14`（灯灭），重跑 `go` 再发车 |
