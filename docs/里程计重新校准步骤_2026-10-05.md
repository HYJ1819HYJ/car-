# 里程计重新校准：全程地面测试

2026-10-05 本轮地面标定结果已记录并应用为默认值：有效轮径 0.166224818 m、有效轮距 0.408879504 m、每轮一圈计数 4096。完整结果见 [里程计校准结果_2026-10-05.md](里程计校准结果_2026-10-05.md)。按用户要求，建图和导航调试留待后续进行。

下文保留本轮采集的完整流程，其中 0.20894 m / 0.51375 m 是采集开始时的旧基线；含旧值的命令用于复现本轮标定过程，不代表当前启动默认值。再次采集请使用新的输出目录，避免覆盖本轮实测记录。
按“地面方向检查 → 直线距离尺度 → 左右转向有效轮距 → 独立复验”执行。全部试验均在地面上完成。
记录工具只记录和计算候选值，不发送运动指令、不自动修改生产参数。
本流程固定 ticks_per_rev=4096，不进行单轮圈数测量；直线试验标定的是米/计数比例。在该固定计数下得到的 wheel_diameter 是有效参数，不等于独立测得的轮胎物理直径。

## 1. 准备

- 在比赛相同地面、正常胎压/载荷、电池状态下测量。准备卷尺、胶带、车头方向标记，建议两人配合。
- 选择有 3 m 直线及完整旋转余量的空地，不在距墙 5 cm 的通道里标定。
- 小车地面位置以驱动轮轴中心的地面投影为基准；旋转角度用车体方向标记与地面角度线测量。
- 在原导航启动终端 Ctrl+C，等整套节点退出。关闭 RViz 窗口不等于关闭导航。已有地图文件保留。此前已关闭小车相关 ROS 进程；若此后没有启动新实例，可直接进行第 2 步，roslaunch 会按需启动 ROS master。
- 手柄须在启动前插好；启动时摇杆回中、LB 松开。试验时按 LB 控制，松开停止。
- 2026-10-05 已修复 rosctl 固定使用 -T 导致的 Ctrl+C 信号丢失：后续在普通交互终端启动会自动保留容器 TTY。结束时按 Ctrl+C，等出现 done 并返回提示符；修复前已启动的实例需先退出再重新启动。
- 全程保留雷达与碰撞保护。工具退出或 Ctrl+C 不会替你停止小车。

## 2. 终端 A：启动标定模式

```bash
r1 roslaunch maze_bridge odom_calibration.launch \
  port:=/dev/ttyUSB0 max_v:=0.10 max_w:=0.25 \
  wheel_diameter:=0.20894 wheel_base:=0.51375 ticks_per_rev:=4096
```

保持终端 A 运行。这一模式仅运行 serial_bridge、odom_publisher、雷达、车体自反射过滤和雷达静态 TF，不运行 SLAM、AMCL、move_base、相机或 RViz。

终端 B 检查：

```bash
r1 rosnode list
r1 rosparam get /odom_publisher
r1 rostopic hz /wheel_encoder
```

最后一个命令观察几秒后 Ctrl+C。反馈应持续，不能存在频繁长间断。需要排查停止时可用：

```bash
r1 rostopic echo /control_source
```

正常手柄控制显示 joystick；停止后 idle。若显示 lidar_timeout_stop、front_emergency_stop、trajectory_collision_stop 等，先检查真实障碍、雷达和机械空间，不解除保护来强行完成试验。

## 3. 地面短距离方向检查

在空地对齐车头，使用手柄向前走约 0.5～1 m。此次只检查方向，不纳入轮径拟合。
终端 B：

```bash
r1 python3 /workspace/xiaoche/tools/record_odom_calibration.py \
  --mode straight --truth 1.00 \
  --output /workspace/xiaoche/outputs/odom_ground_20261005/check_forward.json
```

回车开始 → 手柄 LB+前进摇杆 → 松开 LB、停稳约 1 秒 → 回车结束 → 输入真实测量距离。
检查输出 delta_ticks.left、delta_ticks.right、odom_forward_m 均为正；issues 应为空。
如果实车向前而某轮累计增量为负，或 /odom 显示向后，先暂停后续试验并检查方向/映射，不用负轮径或负轮距补偿。

当前 /wheel_encoder 为 16 位累计计数，物理左轮对应 data[1]，物理右轮对应 data[0]，两侧符号为 +1。记录工具逐帧处理计数器回绕。
固定保留 4096，跳过每圈计数的独立验证；后续全部使用地面真实距离和角度拟合有效尺度。

## 4. 直线标定轮径

地面贴 3.00 m 起终线，车轮轴中心对齐起点、车头对齐直线。在终端 B 执行：

```bash
r1 python3 /workspace/xiaoche/tools/record_odom_calibration.py \
  --mode straight --truth 3.00 \
  --output /workspace/xiaoche/outputs/odom_ground_20261005/straight_01.json
```

1. 小车停稳，回车开始记录。
2. 手柄 LB+前进摇杆，保持直行。先用约 0.08～0.10 m/s，接近终线减速，人工停车。
3. 松开 LB，停稳等待约 1 秒，回车结束。
4. 尺量轮轴中心的真实位移。若实际是 3.02 m，在第三个提示输入 3.02，不能把目标 3.00 m 当成实际距离。
5. 检查 issues 为空；有反馈跳变、过期或未停稳则重测。
6. 记录真实末端偏移/方向误差。若真实轨迹明显弯曲，不能把两端直线距离当路程，应先处理直行问题。

至少做五组，文件名 straight_01～05。调转车头后继续向前做相反方向复验，不需要解除自主倒车限制。每组开始时工具会重新取基准，/odom 无需清零。
不要用 /amcl_pose、RViz 的 map 位姿或“速度指令×时间”作真值。

单组公式：D_new=D_old×S_true/S_odom，其中 S_odom 由累计左右计数平均计算。
示例：真实 3.00 m，里程计 3.15 m，则 D_new≈0.198990476 m；这只是示例。

五组有效记录后，在宿主机拟合：

```bash
python3 "/home/asuka/Desktop/college-level competition/xiaoche/tools/fit_odom_calibration.py" \
  --mode straight \
  "/home/asuka/Desktop/college-level competition/xiaoche/outputs/odom_ground_20261005"/straight_*.json
```

工具使用过原点最小二乘：D_new=D_old×Σ(S_odom×S_true)/Σ(S_odom²)。不同参数批次或含 issues 的组会被拒绝。新目录 odom_ground_20261005 用于本轮地面测试，不混入之前其他批次。实车轨迹弯曲等人工发现的无效组，应移到单独目录，排除拟合。

## 6. 原地左右旋转标定有效轮距

在空地画车头方向基准线，用车体长标记判断实际角度。以低速旋转，人工按真实地面角度停车，不能用里程计或定时器决定实际角度。

左转整圈，终端 B：

```bash
r1 python3 /workspace/xiaoche/tools/record_odom_calibration.py \
  --mode rotate --truth 360 \
  --output /workspace/xiaoche/outputs/odom_ground_20261005/rotate_left_01.json
```

右转整圈：

```bash
r1 python3 /workspace/xiaoche/tools/record_odom_calibration.py \
  --mode rotate --truth -360 \
  --output /workspace/xiaoche/outputs/odom_ground_20261005/rotate_right_01.json
```

开始/结束/实际角度确认的方法与直线相同。左转实际与里程计转角应为正，右转为负；实际左转时物理左轮后退、右轮前进。若符号不符，先检查映射与方向。
左右各至少三组，文件名 01～03。可再用左右 90°、180°交叉验证；整圈最终 yaw 接近起点，工具使用逐帧累加转角，不会把整圈当成零。

单组公式：b_new=b_old×theta_odom/theta_true。例：实际左转 360°，里程计累计 300°，b_new=0.51375×300/360=0.428125 m，仅为示例。
有效轮距包含轮胎接地与滑移影响，不能直接用尺量轮中心距替代。

宿主机拟合左右两方向记录：

```bash
python3 "/home/asuka/Desktop/college-level competition/xiaoche/tools/fit_odom_calibration.py" \
  --mode rotate \
  "/home/asuka/Desktop/college-level competition/xiaoche/outputs/odom_ground_20261005"/rotate_*.json
```

拟合公式 b_new=b_old×Σ(theta_odom×theta_true)/Σ(theta_true²)。先比较单组 candidate_wheel_base_m；左右方向若相差超过约 5% 或同方向重复值差异明显，先检查打滑、拖轮、地面、电量及方向测量，不应只平均后继续。

实车本身走弯和“实车直行但里程计走弯”要分开；当前代码左右共用同一米/计数参数，后者可能需要分别标定左右尺度，不能靠统一轮径完全解决。

## 9. 校准后的范围

本项目 MCU 源码中控制换算 L=407.0 mm，与 ROS 有效轮距的含义和作用不同，且磁盘源码不证明实车烧录版本。先完成以上里程计校准，再比较指令、/odom 速度与外部真实速度；本次不更改 MCU 或烧录固件。
先前导航日志中的长控制周期也不会因为几何校准自动消失；复验导航时仍需关注 /cmd_vel 更新间隔和 /control_source。

公式与源代码依据：本项目 odom_publisher.cpp；[ROS 差速里程计实现](https://github.com/ros-controls/ros_controllers/blob/noetic-devel/diff_drive_controller/src/odometry.cpp)。
