# TEB 仿真速度与转向稳定性调参

同日按用户指定，补充了比赛场地六种箱位的完整 v2/v3 对照（12 次导航），详见 [比赛场地对照结果](TEB比赛场地对照_2026-11-16.md)。该轮五组可达场景总用时下降约 2.0%，规划角速度总变差下降约 26.5%；终点前绕行组略慢，不能把下文早期筛选结果推广为每个场景都更快。

本轮仅测试仿真。代码基线为 `asuka-main` 的 `4fa30b3`，地图、箱位、完整 24 点 STL 轮廓、全局规划、安全门和速度上限保持一致；仿真上限仍为 3 m/s、1 rad/s。

## 当前参数与回退

新增文件：`src/maze_bridge/launch/teb_local_planner_params_v3_sim.yaml`。它是仿真覆盖文件，在 v2 和 `smooth_teb_params.yaml` 之后、命令行速度上限之前加载。

| 参数 | 原 v2 仿真有效值 | v3 仿真值 |
| --- | --- | --- |
| `control_look_ahead_poses` | 插件默认 1 | 2 |
| `weight_optimaltime` | 1.0 | 2.0 |
| `weight_acc_lim_x` | 1.0 | 2.0 |
| `weight_acc_lim_theta` | 5.0 | 10.0 |
| `weight_max_vel_theta` | 5.0 | 8.0 |
| `max_global_plan_lookahead_dist` | 1.6 m | 1.8 m |
| `global_plan_viapoint_sep` | 0.40 m | 0.30 m |
| `weight_viapoint` | 0.5 | 1.0 |

使用两个轨迹区间提取速度指令，配合时间、加速度和路径点权重调整，减少短时转向指令变化并保持前进效率。权重属于优化代价，不是最终输出的硬加速度或 jerk 限制。

v1、v2、共享 `smooth_teb_params.yaml`、实车启动文件、安全门源码、车体轮廓和局部代价地图文件均通过 SHA-256 检查，内容未改。实车仍按原 v2 启动，默认 0.50 m/s、0.75 rad/s。

仿真默认 `optimize_teb:=true`；添加 `optimize_teb:=false` 即回到原 v2 对照，无需修改参数文件。修改 v3 后重启仿真生效，无需重新编译。

## 同机对照结果

使用 Noetic、TEB 0.9.1、GUI Stage、独立 ROS master 11329。每次重启场景，从相同起点导航到相同终点；没有加载实车串口或硬件雷达节点。

下表使用相同机器的少量样本：`01_open` 每个配置各跑 2 次取均值，`03_lower_reroute` 各跑 1 次。时间从 demo 发布 RUNNING 到最终结果，含约 1 秒停车观察。

| 场景 | 原 v2 用时 | v3 用时 | 用时下降 | 规划角速度总变差下降 |
| --- | --- | --- | --- | --- |
| `01_open` | 15.36 s | 14.83 s | 3.4% | 31.2% |
| `03_lower_reroute` | 15.05 s | 14.39 s | 4.4% | 29.2% |

“角速度总变差”定义为连续 `/simulation/nav_cmd_vel.angular.z` 样本的 `sum(abs(w[i]-w[i-1]))`。相同路线和相近用时下，较小值反映转向指令变化减少；它不等于机械摆动测量。两个对照场景的规划角加速度绝对值 P95 分别从 3.79→2.84、3.24→2.75 rad/s²，也只是离散输出指标。

还试过较保守的候选和 `weight_optimaltime=3` 的候选。后者在单次筛选中转向变化与安全门拦截更多、最小墙边间隔更小，未作为默认参数。

## 六组场景复核

| 场景 | v3 状态 | 用时 | 碰撞采样 | 倒车指令 |
| --- | --- | --- | --- | --- |
| `01_open` | SUCCEEDED | 15.11 s | 0 | 0 |
| `02_upper_reroute` | SUCCEEDED | 15.05 s | 0 | 0 |
| `03_lower_reroute` | SUCCEEDED | 14.39 s | 0 | 0 |
| `04_divider_detour` | SUCCEEDED | 16.20 s | 0 | 0 |
| `05_finish_approach` | SUCCEEDED | 16.20 s | 0 | 0 |
| `06_blocked_exit` | FAILED，符合预期 | 31.22 s | 0 | 0 |

封堵组没有移动，最终实际速度为零，报告无可行路径。五组可达场景均到达目标并停车。所有组均验证导航底图一致、两个新增箱体有激光/代价地图观测。可达组没有观察到大于 0.5 秒的规划指令间断。

这轮仿真估计的新箱最小几何间隔约为 9.5 cm。`min_obstacle_dist=0.10` 保持原值，但属于软优化偏好，不能把它解释为全程至少 10 cm 的物理保证。

## 启动

常规 Docker 环境正常时，在宿主机运行：

```bash
cd '/home/asuka/Desktop/college-level competition/xiaoche'
./start-competition-sim.sh \
  scenario:=01_open demo:=false show_rviz:=true \
  max_nav_v:=3 max_nav_w:=1
```

回退到 v2：在同一条命令末尾加 `optimize_teb:=false`。先在启动终端按 Ctrl+C，等待旧仿真退出，再启动另一组配置。

### 本机无硬件验证容器

本轮常规 Compose 因未连接的 STM32 设备映射无法启动，所以使用独立容器 `xiaoche-teb-tune-20261116`，没有设备映射，采用软件 OpenGL；测试完成后停止容器。该容器及以下辅助脚本仅存在于本机，不是仓库安装依赖。

如本机设备仍未连接，可先退出已有仿真、确认 11329 端口空闲，再从宿主机执行：

```bash
cd '/home/asuka/Desktop/college-level competition/xiaoche'
python3 ../tools/refresh_ros_gui_auth.py \
  /home/asuka/Documents/Codex/2026-10-02/24-04-ros1-ros2-cubemx-clino/outputs/ros-docker/data/gui
docker start xiaoche-teb-tune-20261116
docker exec -it xiaoche-teb-tune-20261116 bash \
  /workspace/xiaoche/outputs/teb_tuning_20261116/run_ros.sh \
  roslaunch --port 11329 competition_sim navigation.launch \
  scenario:=01_open demo:=false show_rviz:=true \
  max_nav_v:=3 max_nav_w:=1
```

退出 roslaunch 后可执行 `docker stop xiaoche-teb-tune-20261116`。不要在已有仿真运行时重复启动。

## 证据与边界

本地 `outputs/teb_tuning_20261116/` 保存每次试验的完整参数、临时启动文件、`result.json`、`metrics.json`、速度样本和日志，另有 `comparison.json`、`configuration_verification.json` 和 `command_comparison.png`。v1/v2、实车入口与安全/几何文件的 SHA-256 保存在 `preserved_sources.json`。

结果只覆盖这些静态新增箱体仿真，不覆盖 DWA 分支的搬移箱体地图更新或实车。样本少、定位及调度有随机性，不能保证所有场景均有相同百分比提升。Stage 的瞬时速度响应不能用于证明真实底盘的加速度、制动距离或机械稳定性。本轮未运行实车。

参数语义依据 [TEB 配置定义](https://github.com/rst-tu-dortmund/teb_local_planner/blob/noetic-devel/cfg/TebLocalPlannerReconfigure.cfg) 与 [速度命令提取实现](https://github.com/rst-tu-dortmund/teb_local_planner/blob/noetic-devel/src/teb_local_planner_ros.cpp)。实际参数支持情况已对照本机安装的 TEB 0.9.1 头文件和运行结果检查。
