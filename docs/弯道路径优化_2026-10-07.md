# 2026-10-07 弯道路径与转向约束优化

用户现象：车体左侧有空间，但导航路径仍贴右侧内弯障碍，转弯慢或停住。目标是在车身之外争取 5–10 cm 间隙，允许适度绕远，避免内侧切角。

本次配置已经写入工程，依赖 global_planner 已安装到 Noetic 容器。没有修改正在运行的导航参数，没有向实车发送速度、目标或初始化位姿。需要退出旧导航后重启才生效。未改里程计校准、底盘固件、真实车体尺寸和串口碰撞保护。

## 原因与实现范围

Navfn 本身也会考虑栅格代价，不能简单归结为“只求几何最短路径”。但当前全局软代价带只到 0.26 m；車身半宽 0.24 m，加上角点旋转空间后，全局中心线依然可能贴内侧。TEB 的路径点权重 8.0 又强迫局部轨迹靠近这条参考线。

本次用可明确配置代价权重的 `global_planner/GlobalPlanner` 执行 Dijkstra 代价搜索，梯度路径提取。全局障碍软代价带扩到 0.40 m，同时减弱 TEB 对参考线的束缚，让局部轨迹有机会向外侧移动。它是可通行区域中的选路偏好，不是把车身外安全距离设为 40 cm；局部代价地图膨胀仍为 0.25 m。

全局算法仍为二维位置搜索，不是在全局直接搜索转向时间或车体朝向。朝向、车体多边形、角速度、角加速度及行驶时间由 TEB 局部轨迹优化处理。本次加强角速度/角加速度约束权重，保留时间优化，取消额外最短长度惩罚。没有给差速底盘添加阿克曼舵角约束，也没有提高转速。

真实车体 footprint 仍为 `[[0.3483,0.24],[0.3483,-0.24],[-0.1517,-0.24],[-0.1517,0.24]]`。串口安全碰撞 padding 仍为 0.02 m，前后停车阈值仍为 0.15 m，禁止导航后退。5–10 cm 为规划偏好；优化权重和地图栅格误差使其不构成任何位置都满足的几何保证，也不强制每一处都从左侧绕。

## 已执行验证

证据目录：`outputs/corner_planning_20261007/`。

1. 已知矩形障碍、90°内弯场景，在独立 master 上调用真正的 `/move_base/make_plan`，没有下发运动目标。原参数和新参数使用相同地图、起点和终点。

| 指标 | 原配置 | 新配置 |
|---|---:|---:|
| 路径长度 | 3.669 m | 3.777 m |
| 拐角处参考点到占据栅格距离 | 0.263 m | 0.404 m |
| 拐角处车身间隙估算 | 接近零 | 0.102 m |

车身间隙估算使用平滑路径切线作为车体朝向，完整多边形相对占据栅格计算距离并扣除半个栅格对角线。这是全局参考线的几何检查，不是 TEB 轨迹可行性证明，也不是实际场地的测量。新路径长度只增加约 3%，主动绕开了内弯。

2. 使用已有停车传感器记录回放，独立 master `11314`，只播放 `/scan /odom /tf`，地图和静态 TF 单独锁存。无硬件节点，速度仅发送到 `/diagnostic/cmd_vel`。实际加载 GlobalPlanner 的最终回放 13 s 中输出 156 条速度，其中非零 155 条，最大输出间隔 0.195 s，没有超过 0.5 s 的间断；最大线速度 0.10 m/s、最大角速度 0.25 rad/s。存在个别 12 Hz 调度超时日志，不能宣称每周期均达到 12 Hz。回放关闭振荡超时和恢复行为，仅用于输出时延诊断；生产仍保留原设置。

3. 生产启动文件只读执行 `roslaunch --dump-params`，验证新规划器、代价/TEB参数、保留的标定及安全参数，并验证 RViz 路径 topic、包依赖和真实 footprint。`verify_corner_change.py` 中的断言实际执行并通过；`verification.json` 保存结果。

以上支持“路径愿意绕开内侧，且该回放没有命令超时”，不能证明真实小车已经顺畅过弯。激光与地图错位、定位误差、底盘实际角速度与指令不一致仍可能影响结果。

## 实车重启命令

在原导航终端按 Ctrl+C，等整套 launch 返回 shell 提示符后，在终端 A 执行：

```bash
"/home/asuka/Desktop/college-level competition/xiaoche-ros1.sh" \
  roslaunch maze_bridge navigation_stack.launch \
  mode:=navigation \
  map_file:=/workspace/xiaoche/maps/competition_map_calibrated_20261007.yaml \
  port:=/dev/ttyUSB0 \
  wheel_diameter:=0.166224818 \
  wheel_base:=0.408879504 \
  ticks_per_rev:=4096 \
  max_v:=0.10 \
  max_nav_v:=0.10 \
  max_nav_w:=0.25 \
  camera_device:=/dev/video4 \
  enable_blue_autonomy:=false \
  show_rviz:=true
```

使用 2D Pose Estimate 对齐当前实际位置和朝向，确认雷达墙线与地图墙线重合，再发送原来的弯后目标。看全局线是否向外绕、局部线是否留出车体间隙，以及是否仍出现 Full-footprint collision predicted 等日志。

当前转速上限 0.25 rad/s，完成 90°方向变化理论上至少需要约 6.28 s（实际还包含加减速）。以 0.10 m/s 不减速转弯，对应圆弧半径至少 0.40 m。路线优化不能消除这一物理时间限制；转速参数应以地面实际转向测试为依据再调整。

终端 B 可只读确认：

期望分别看到新插件名、0.05、0.10，以及 radius=0.40、scaling=4.0。不要同时启动第二套导航/建图。

## 回退本次修改

如需恢复本次修改前的规划，在停止导航后运行以下文件恢复命令，再用原启动命令重启。原 Navfn 包仍保留。新全局配置文件留在工程中但原 launch 不加载它。

```bash
python3 - <<'PY'
from pathlib import Path
import shutil
root = Path('/home/asuka/Desktop/college-level competition/xiaoche')
backup = root / 'outputs/corner_planning_20261007/before'
for relative in [
    'src/maze_bridge/launch/navigation_stack.launch',
    'src/maze_bridge/launch/teb_local_planner_params.yaml',
    'src/maze_bridge/launch/global_costmap_params.yaml',
    'src/maze_bridge/rviz/gmapping.rviz',
    'src/maze_bridge/package.xml',
    'setup_ros_noetic.sh',
]:
    shutil.copy2(backup / relative, root / relative)
PY
```

算法参数依据：[GlobalPlanner 实现](https://github.com/ros-planning/navigation/blob/noetic-devel/global_planner/src/planner_core.cpp)、[TEB 权重与约束定义](https://github.com/rst-tu-dortmund/teb_local_planner/blob/noetic-devel/cfg/TebLocalPlannerReconfigure.cfg)。
