【🎯 为什么必须SLAM？】

你的真实比赛场景：
  ✗ 终点位置每次都不同（"会在黑线上随机变化"）
  ✗ 动态障碍物位置每次都变（"位置在每次任务开始之前随机变化"）
  
所以教学记录（固定轨迹）不行！

你需要SLAM来：
  ✓ 建立完整的环境地图
  ✓ 根据当前的终点位置实时规划路径
  ✓ 实时避开新出现的动态障碍物

【📊 RViz界面解读】

【建图模式 - gmapping_build_map.launch】

显示内容：
  ✓ 黄色点   = 激光扫描数据（实时）
  ✓ 绿色区域 = 已探索的开放空间
  ✓ 黑色区域 = 障碍物
  ✓ 灰色区域 = 未探索区域

正常现象：
  ✓ 小车移动时，地图实时更新
  ✓ 黄色点会跟随小车移动
  ✓ 逐渐扫描出完整的迷宫地图

异常现象（需要排查）：
  ✗ 地图全黑或全白   → 激光雷达无数据
  ✗ 地图不更新        → Gmapping节点可能崩溃
  ✗ 地图乱飘          → TF树配置有问题


【导航模式 - navigation_stack.launch mode:=navigation】

显示内容：
  ✓ 灰黑色地图 = 已建立的地图（静态）
  ✓ 红色箭头   = 小车当前位置和方向
  ✓ 绿色路径   = 规划好的导航路径
  ✓ 蓝色轨迹   = 小车实际走过的轨迹

正常现象：
  ✓ 点击目标点后，出现绿色路径
  ✓ 小车沿着绿色路径移动
  ✓ 实际轨迹（蓝色）跟踪规划路径（绿色）
  ✓ 绿色路径避开黑色障碍物

异常现象（需要排查）：
  ✗ 点击目标点后没有路径出现  → move_base无法规划
  ✗ 路径穿过障碍物            → 代价地图配置问题
  ✗ 小车不跟踪规划路径        → 局部规划器失效


【🔍 故障排查】

问题1️⃣：建图时地图为全黑或全白

排查步骤：
  $ rostopic list | grep scan
  应该看到 /scan 话题
  
  $ rostopic echo /scan | head -20
  应该看到大量的范围数据（ranges: [])
  
  如果看不到数据：
    → 激光雷达没有启动或连接断开
    → 检查 lsusb（应该看到设备）
    → 检查 ls /dev/ttyUSB*（应该有设备文件）

问题2️⃣：导航时小车不动或走不对

排查步骤：
  $ rosnode list
  应该看到：
    /move_base
    /amcl
    /map_server
    
  如果缺少节点，检查导航栈的启动状态
  
  $ rostopic echo /cmd_vel | head -10
  应该看到速度指令数据
  如果没有，move_base可能没有规划成功

问题3️⃣：小车容易撞到障碍物

原因：代价地图的膨胀半径太小

解决：
  编辑 src/maze_bridge/launch/costmap_common_params.yaml
  增加 inflation_radius 值（从 0.5 改为 1.0）
  
  然后重新运行导航栈


【⏱️ 完整测试流程】

第1天：基础验证（< 1小时）
────────────────────────────
1. 编译项目
   $ cd ~/xiaoche && catkin_make -j4

2. 启动建图（空场地或简单环境）
   $ roslaunch maze_bridge gmapping_build_map.launch show_rviz:=true
   • 让小车走一圈
   • 确保地图能生成
   • 检查 ~/.ros/maze_map.yaml

3. 启动导航
   $ roslaunch maze_bridge navigation_stack.launch mode:=navigation
   • 点击目标点
   • 小车能否到达
   • 观察避障情况

成功标志：✓ 地图能生成，✓ 小车能导航

第2天：迷宫测试（2-3小时）
────────────────────────────
1. 设置真实迷宫环境

2. 完整流程测试（3次）
   • 第1轮：建图
   • 第2轮：导航到预定终点
   • 第3轮：改变目标点，再导航一次

3. 测试不同的导航目标
   • 在地图的不同位置设置目标点
   • 验证小车能从各种位置出发并到达

4. 测试避障
   • 建图时，摆放所有固定障碍物
   • 导航时，在原轨迹上添加新障碍物
   • 验证小车能绕过新障碍物

成功标志：✓ 完整3轮都成功，✓ 能避开动态障碍物

第3天-第7天：优化与压力测试（每天1-2小时）
─────────────────────────────
1. 参数调优
   • 如果导航太慢，增加 max_vel_x
   • 如果容易撞障碍，增加 inflation_radius
   • 如果建图精度不够，增加 particles

2. 长时间运行测试
   • 连续运行20分钟（完整一轮比赛时间）
   • 检查系统稳定性
   • 检查是否有崩溃或卡顿

3. 重复多次迷宫测试
   • 熟悉整个流程
   • 找到最优的建图方式
   • 找到最快的导航速度

成功标志：✓ 系统稳定，✓ 参数最优


【🎯 关键参数](#/location=gmapping_build_map.launch)

【如果建图太差】
在 gmapping_build_map.launch 中：
  particles: 30 → 100   （增加粒子数）
  map_update_interval: 2.0 → 1.0   （更频繁更新）

【如果建图太慢】
  particles: 30 → 15    （减少粒子数，牺牲精度）
  或者放慢小车速度（0.1 m/s）

【如果导航太快，容易撞障碍】
在 navigation_stack.launch 或 dwa_local_planner_params.yaml：
  max_vel_x: 0.3 → 0.2  （降低速度）

【如果导航太慢】
  max_vel_x: 0.3 → 0.5  （提高速度）

【如果总是贴着障碍物】
在 costmap_common_params.yaml：
  inflation_radius: 0.5 → 1.0  （增加安全距离）

【💡 关键建议】

✅ 建图时的最佳做法：
  1. 让小车尽可能慢（0.1-0.2 m/s）
  2. 走遍整个迷宫的所有区域
  3. 重点扫描起始线到终点线之间的路径
  4. 完成一个"之字形"或"螺旋形"覆盖

✅ 导航时的最佳做法：
  1. 点击目标点时要准确（点在黄色区域中心）
  2. 第一次导航如果失败，分析原因再重试
  3. 不要更改地图或重新建图（浪费时间）
  4. 利用好3次重试机会

❌ 常见错误：
  ✗ 建图时走太快 → 地图不清晰
  ✗ 建图时没有覆盖全场 → 导航时找不到路
  ✗ 导航时点错目标位置 → 走向错误的地方
  ✗ 第一次失败就放弃 → 还有2次机会
