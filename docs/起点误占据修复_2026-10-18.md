## 验证

network=none、无串口/雷达设备的独立容器使用实际 Noetic move_base 和当前插件验证同一起点、同一目标：

| 地图 | 有效路径点 | 起点可用 | 目标可用 |
| --- | ---: | --- | --- |
| 原图 | 0 | 否 | 是 |
| 仅修正 14 栅格的副本 | 200 | 是 | 是 |

修正图已加载到实际导航节点。真实 /move_base/make_plan 返回 200 个有效点，start_free=true、goal_free=true、valid=true；没有发送 action 行驶目标，观测到的非零底盘发送指令数量为 0。实车运动和过弯效果仍待用户现场测试。

验证时另外发现：上游 make_plan 服务默认会清理小车周围的代价地图窗口。因此已在 navigation_stack.launch 明确设置 make_plan_clear_costmap=false 和 make_plan_add_unreachable_goal=false，使预览保留原有障碍约束。上述原图/修正图对照与实车预览均在这两个开关关闭时进行。

原理依据：[ROS Noetic move_base 实现](https://raw.githubusercontent.com/ros-planning/navigation/noetic-devel/move_base/src/move_base.cpp)。

证据目录：outputs/no_motion_20261018/current/，其中 startfix.json 记录修改栅格，offline_result.json 记录隔离对照，live_preview.json 记录实际节点预览。导航启动日志为 navigation_startfix.log。

## 现在如何测试

导航和 RViz 已启动，无需重复启动。先关闭 RViz 的 ROS1 生命周期提示框（若有），确认显示位置与实车一致，再重新设置 2D Nav Goal。

之后需要重新启动时使用修正副本：

```bash
cd "/home/asuka/Desktop/college-level competition"
./xiaoche-ros1.sh roslaunch maze_bridge navigation_stack.launch \
  mode:=navigation \
  map_file:=/workspace/xiaoche/maps/competition_map_20261018_dynamic_startfix.yaml \
  port:=/dev/ttyUSB0 baud:=115200 camera_device:=/dev/video4 \
  max_v:=0.10 max_nav_v:=0.10 max_nav_w:=0.25 \
  corner_clearance:=true corner_extra_clearance:=0.05 corner_scope:=main_walls \
  use_stl_footprint:=true \
  safety_enable:=true enable_blue_autonomy:=false use_gimbal:=false show_rviz:=true
```

重新启动后按实车位置使用 2D Pose Estimate 定位。不要在当前导航尚未退出时再启动第二套节点。
